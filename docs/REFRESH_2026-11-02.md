## AI boundary
The existing authenticated server gateway now validates purpose (recipe/design/health/calories), includes purpose in the cache key and preserves quota/cost controls. Design/health/calorie answers return plain notes, with explicit constraints for health and uncertain nutrition. OpenAI Responses documentation: https://developers.openai.com/api/reference/responses/overview

GitHub Pages is static: no server or AI credentials are published. Real AI calls require a separately running configured API and an authenticated account; the published UI reports this honestly. No live paid provider call was made. Social video audio/frame/transcript retrieval is not connected. Links are stored as sources; text/transcript and screenshots can be supplied manually. PDF is accepted for local storage; this AI path accepts images only. Example conversations are visibly labelled, never substituted as live answers.
