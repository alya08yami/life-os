# LIFE OS — полное техническое задание на обновление приложения

## 0. Контекст и основная задача

Мы разрабатываем мобильное приложение **LIFE OS** — визуальный персональный органайзер с дополнительными AI-функциями.

В проекте уже существуют первые наброски экранов и часть реализации. Твоя задача — **проанализировать текущий проект, сохранить работоспособные компоненты и архитектуру, переработать интерфейс и постепенно реализовать функциональность согласно этому техническому заданию**.

Не создавай новый проект без необходимости. Не удаляй существующие функции, данные, навигацию или рабочие интеграции без предварительной проверки.

Если какие-то требования уже реализованы, проверь их соответствие спецификации и доработай.

### Главная философия приложения

LIFE OS — не трекер продуктивности, не дневник привычек и не приложение для «идеальной жизни».

Оно предназначено для обычных повседневных потребностей:

- сохранять понравившиеся товары;
- сравнивать цены;
- хранить рецепты;
- планировать покупки;
- сохранять фильмы и сериалы;
- организовывать поездки;
- управлять домашними делами;
- отслеживать регулярные задачи;
- хранить полезную информацию;
- не держать всё в голове.

**Ключевой принцип: пользователь не должен тратить много времени на организацию информации. Приложение должно выполнять максимально возможную часть работы самостоятельно.**

ИИ используется только там, где он действительно полезен. Обычные действия — отображение данных, сортировка, поиск, напоминания, навигация — должны работать без постоянных запросов к нейросети.

# ЧАСТЬ II. ГЛАВНЫЙ ЭКРАН

## 2. Экран Home / LIFE OS

### Верхняя часть

Сверху:

- Слева — иконка меню.
- По центру — `LIFE OS` с увеличенным расстоянием между буквами.
- Справа — иконка поиска.

Не показывать имя пользователя, приветствие, дату ради украшения или мотивационные фразы.

### Основная область

Визуальная сетка из двух колонок.

Каждая категория представлена фотографией с аккуратным названием.

Основные категории:

1. Хотелки
2. Дом
3. Здоровье
4. Питание
5. Фильмы
6. Поездки
7. Гардероб
8. Работа и идеи

Дополнительно:

9. Мои дела
10. Входящие

«Мои дела» и «Входящие» могут быть компактными карточками под основной сеткой либо доступны из нижней навигации.

### Карточки категорий

Карточка содержит:

- Фотографию.
- Название.
- Мягкое скругление.
- При необходимости лёгкий градиент исключительно для читаемости текста.

Не отображать количество элементов в категориях.

Нажатие открывает соответствующий раздел.

### Персонализация главной

Пользователь должен иметь возможность:

- Менять порядок категорий.
- Скрывать ненужные категории.
- Возвращать скрытые категории.
- Выбирать избранные разделы.

Для этого добавить пункт «Настроить главную» в меню.

**Важно:** скрытие категории не должно удалять её содержимое.

Пример: пользователь не пользуется «Гардеробом». Он скрывает карточку с главной, но раздел и сохранённые вещи остаются доступными через меню настроек.

### Быстрые действия

Под категориями можно разместить компактную панель:

- Добавить
- Разобрать
- Сравнить
- Регулярное

Не превращать эту панель в отдельный большой блок.

### Нижняя навигация

Предлагаемая структура:

- Главная
- Поиск
- Добавить
- Мои дела
- Профиль

Центральная кнопка добавления может быть немного выделена, но без чрезмерной яркости.

# ЧАСТЬ III. ХОТЕЛКИ

## 3. Экран «Хотелки»

Это один из ключевых разделов приложения.

### Верхняя часть

- Стрелка назад.
- Заголовок «Хотелки».
- Кнопка `+`.

Под заголовком фильтры:

- Все
- Косметика
- Одежда
- Техника
- Дом
- Другое

Фильтры горизонтально прокручиваются.

### Сетка товаров

Две колонки.

Каждая карточка содержит:

1. Фото товара.
2. Маленькую иконку сердечка.
3. Название товара.
4. При необходимости модель или бренд.
5. Минимальную подтверждённую цену.
6. Индикатор изменения цены, если имеется история.
7. Возможность открыть карточку товара.

Пример:

**Jo Malone**

English Pear & Freesia

**от 4 990 ₴**

Не перегружать карточку длинными описаниями.

### Размещение цены

Цена должна быть видна сразу в сетке, без открытия товара.

Предпочтительный вариант — под фотографией, непосредственно рядом с названием.

Допускается аккуратная ценовая метка в нижней части изображения, если она не закрывает товар.

Не использовать большие цветные баннеры.

### Логика цены

Различать:

- Минимальную найденную цену.
- Реальное снижение цены.
- Повышение цены.
- Отсутствие достоверной цены.

Нельзя показывать зелёную стрелку вниз только потому, что найден самый дешёвый магазин.

Зелёная стрелка появляется исключительно при подтверждённом снижении относительно ранее сохранённой цены.

Если цена не найдена, показывать «Цена не найдена» или «Проверить цену».

### Сортировка

Добавить:

- Сначала дешёвые.
- Сначала дорогие.
- Недавно добавленные.
- По названию.
- Снизилась цена.

### Управление карточкой

По долгому нажатию или нажатию на меню `⋯`:

- Открыть.
- Изменить.
- Переместить в категорию.
- Скрыть с экрана.
- Архивировать.
- Удалить.

**Скрыть, архивировать и удалить — разные действия.**

Скрытие убирает карточку из текущей сетки без потери данных.

Архивирование переносит её в архив.

Удаление требует подтверждения и по возможности поддерживает восстановление через корзину.

Добавить возможность просмотра скрытых и архивных элементов.

### Добавление товара

При нажатии `+` открыть нижнее модальное меню:

- Из скриншота.
- Из фотографии.
- По ссылке.
- Вручную.
- Из «Входящих».

Если товар добавляется из скриншота или фотографии:

1. Распознать изображение.
2. Определить название и бренд, если возможно.
3. Предложить категорию.
4. Найти соответствующий товар.
5. Показать предварительную карточку.
6. Дать пользователю исправить ошибки.
7. Сохранить.

Не считать распознанные данные достоверными без проверки.

## 4. Экран конкретного товара

Большое качественное изображение.

Под ним:

- Название.
- Бренд.
- Характеристики.
- Минимальная найденная цена.
- Дата последней проверки цены.

Ниже блок «Сравнение цен».

### Список магазинов

Для каждого предложения:

- Название магазина.
- Цена.
- Валюта.
- Стоимость доставки, если известна.
- Наличие, если известно.
- Ссылка на конкретный товар.
- Дата проверки.

Пример:

Notino — 4 990 ₴

MAKEUP — 5 240 ₴

Brocard — 5 290 ₴

Это пример условных данных для дизайна, не реальные текущие предложения.

Самое выгодное подтверждённое предложение можно деликатно выделить.

Если доставка известна, сравнивать итоговую стоимость с доставкой, а не только цену товара.

### Кнопки

- Открыть магазин.
- Отслеживать цену.
- Сравнить с другим товаром.
- Поделиться.
- Отметить как купленное.

### Отслеживание цены

Пользователь самостоятельно включает уведомления.

Возможные условия:

- При любом снижении.
- При достижении конкретной цены.
- При снижении на заданный процент.

Не включать уведомления без согласия.

### Повторная покупка

После нажатия «Куплено» предложить:

«Напомнить купить снова?»

Пользователь может выбрать интервал.

Особенно полезно для косметики, бытовой химии и расходников.

## 5. Экран сравнения товаров

Возможность выбрать два или три товара.

Отображать их рядом.

Сравнивать:

- Название.
- Фото.
- Цену.
- Объём или размер.
- Основные характеристики.
- Доступность.
- Магазины.

Для косметики — состав, объём, тип продукта, если данные достоверны.

Для техники — технические характеристики.

Для одежды — материал, размер, бренд.

Не придумывать характеристики и отзывы.

Если AI формирует краткий вывод, он должен основываться на подтверждённых данных.

Не делать категоричных выводов о качестве или стойкости парфюмерии без источников.

# ЧАСТЬ V. МОИ ДЕЛА

## 8. Единый центр задач

Все задачи из разных разделов должны собираться в одном месте.

Например:

- Купить корм для кота — из «Дома».
- Принять назначенное лекарство — из «Здоровья».
- Забронировать отель — из «Поездок».
- Купить ингредиенты — из «Питания».
- Посмотреть фильм — из «Фильмов», если пользователь сам создал такую задачу.

### Вкладки

- Сегодня.
- Неделя.
- Позже.
- Регулярные.

### Карточка задачи

Содержит:

- Чекбокс.
- Название.
- Дату и время, если установлены.
- Иконку категории.
- Индикатор повторения.
- Назначенного участника, если задача общая.

### Действия

- Выполнить.
- Отложить.
- Изменить.
- Перенести.
- Сделать регулярной.
- Удалить.

При выполнении задача не должна бесследно исчезать из истории.

### Важное требование

Не создавать задачи автоматически из любого сохранённого объекта.

Сохранение фильма не означает, что человек обязан его посмотреть сегодня.

Сохранение товара не означает, что его обязательно нужно купить.

Задача создаётся только по действию пользователя или по заранее включённому правилу.

# ЧАСТЬ VI. ВХОДЯЩИЕ

## 10. Экран «Входящие»

Это важнейший механизм обработки информации.

Пользователь может отправлять в приложение:

- Скриншоты.
- Фотографии.
- Ссылки.
- Текст.
- Голосовые заметки.
- Видео, если формат поддерживается.

### Назначение

«Входящие» — временное место для информации, которую ещё не разобрали.

Это не отдельный бесконечный архив.

### Интерфейс

Верхний заголовок «Входящие».

Вкладки:

- К разбору.
- Обработано.

Элементы показываются в виде визуальных карточек.

Для каждого элемента:

- Превью.
- Тип материала.
- Источник, если известен.
- Предполагаемая категория.
- Статус обработки.

### Массовая обработка

Кнопка «Разобрать».

Пользователь может выбрать сразу несколько материалов.

Например, шесть скриншотов:

- Духи.
- Рецепт пасты.
- Красивое место.
- Пальто.
- Фильм.
- Сумка.

Приложение определяет категории и предлагает создать соответствующие карточки.

### Процесс

1. Получить файлы.
2. Создать элементы со статусом `pending`.
3. Запустить распознавание.
4. Получить структурированные данные.
5. Показать предварительный результат.
6. Дать пользователю проверить.
7. Сохранить в нужные разделы.
8. Перевести элементы в `processed`.

Если распознавание не удалось, сохранить оригинальный материал и показать возможность ручного разбора.

### Возможные статусы

- `pending`
- `processing`
- `needs_review`
- `processed`
- `failed`

### Действия с материалами

- Разобрать.
- Выбрать категорию.
- Изменить.
- Сохранить.
- Архивировать.
- Удалить.
- Повторить обработку.

### Интеграция с системным меню «Поделиться»

Если платформа позволяет, реализовать Share Extension / Android Sharesheet.

Пользователь должен иметь возможность отправить ссылку или изображение в LIFE OS из другого приложения.

Не обещать автоматический доступ к содержимому закрытых соцсетей.

Если видео по ссылке недоступно, предложить загрузить файл или сохранить ссылку без обработки.

- `placeId`, если получен через Google Places.

- SDK для Android и iOS.
- API-ключи.
- Ограничения ключей.
- Биллинг.
- Квоты.
- Правила хранения данных.
- Правила использования фотографий.
- Атрибуцию.

Для первого этапа достаточно надёжно открывать место во внешнем Google Maps через официальные ссылки.

# ЧАСТЬ XVII. УДАЛЕНИЕ, СКРЫТИЕ И АРХИВ

## 25. Единая система управления материалами

Для всех поддерживаемых карточек предусмотреть:

- Изменить.
- Скрыть.
- Архивировать.
- Удалить.

### Скрыть

Карточка не отображается в основном списке.

Данные сохраняются.

### Архивировать

Карточка переносится в архив.

### Удалить

Карточка перемещается в корзину, если предусмотрено восстановление, либо удаляется после подтверждения.

Для необратимого удаления явно предупреждать пользователя.

### Восстановление

В настройках:

- Скрытые элементы.
- Архив.
- Корзина.

При удалении связанных материалов не удалять автоматически независимые объекты.

Например, удаление рецепта не должно неожиданно удалять уже созданный список покупок.

# ЧАСТЬ XXI. ПОВЕДЕНИЕ ИНТЕРФЕЙСА

## 29. Обязательные состояния

Для каждого экрана реализовать:

- Загрузка.
- Пустое состояние.
- Успешная загрузка.
- Ошибка.

Не использовать навязчивые фразы.

«Здесь будут сохранённые товары».

Для «Фильмов»:

«Пока нет сохранённых фильмов».

Кнопка: «Добавить фильм».

- Плавные переходы.
- Корректная работа кнопки «Назад».
- Удобные зоны нажатия.
- Поддержка системных размеров текста.
- Контрастность.
- Доступность для экранных дикторов.
- Подтверждение опасных действий.
- Отмена действия там, где возможно.

Не жертвовать удобством ради красивого макета.

# ЧАСТЬ XXIV. КРИТЕРИИ ГОТОВНОСТИ

## 32. Что должно работать после обновления

Минимальные сквозные сценарии:

### Сценарий A — товар

Пользователь открывает «Хотелки», добавляет товар, видит фото и цену, открывает карточку, редактирует её, скрывает, восстанавливает и удаляет.

Если доступен реальный сервис предложений, видит проверенные цены магазинов.

### Сценарий B — рецепт

Пользователь сохраняет рецепт, открывает ингредиенты, выбирает нужные и добавляет их в список покупок.

### Сценарий C — фильм

Пользователь добавляет фильм, видит постер, открывает подробности, меняет статус просмотра и удаляет запись.

### Сценарий D — место

Пользователь сохраняет место, открывает его в Google Maps и добавляет в поездку.

### Сценарий E — регулярная задача

Пользователь создаёт задачу с повторением, получает напоминание, отмечает выполнение и видит следующую дату.

### Сценарий F — входящие

Пользователь добавляет несколько скриншотов, получает результаты распознавания, исправляет категории и сохраняет материалы.

### Сценарий G — персонализация

Пользователь скрывает «Гардероб» с главной, перезапускает приложение, видит сохранённую настройку и может вернуть раздел.

### Сценарий H — приватность

Пользователь создаёт общее пространство, приглашает участника и видит только те данные, которыми явно поделился.

# ЧАСТЬ XXV. ПОРЯДОК РАБОТЫ CODEX

## 33. Инструкция по выполнению

Сначала выполни аудит проекта.

Предоставь:

1. Какие технологии используются.
2. Какие экраны уже существуют.
3. Какие компоненты можно переиспользовать.
4. Какие требования уже выполнены.
5. Какие изменения потребуются в базе данных.
6. Какие интеграции требуют ключей, биллинга или внешних сервисов.
7. Какие функции можно реализовать сразу.
8. Какие функции нужно отложить.

После аудита предложи поэтапный план.

Затем начни с обновления дизайн-системы, главного экрана, навигации и основных карточек.

**Не выполняй масштабный рефакторинг всего приложения одним большим изменением.**

После каждого этапа:

- Проверяй сборку.
- Исправляй ошибки.
- Проверяй навигацию.
- Проверяй сохранение данных.
- Добавляй необходимые тесты.
- Показывай список изменённых файлов.
- Указывай, что реально работает, а что пока является UI-прототипом.

Если обнаружена архитектурная проблема, объясни её до существенных изменений.

Конечная цель — не набор красивых статичных экранов, а стабильное, визуально привлекательное приложение с понятной архитектурой и постепенно расширяемой функциональностью.

**Главный продуктовый принцип LIFE OS: человек сохраняет информацию один раз и получает возможность использовать её там, где она действительно нужна, без постоянной ручной организации.**
