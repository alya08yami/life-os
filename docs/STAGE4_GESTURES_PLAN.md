**Где возможны конфликты:**
- **Правый край экрана** — там уже работает `SwipeBack`: свайп строки влево от края запустил бы «Назад».
- **Левый край** — системный «назад» iOS и Android.
- **Вертикальная прокрутка** — короткий косой жест не должен считаться свайпом.
- **В браузере** без `touch-action: pan-y` горизонтальный жест блокирует прокрутку.
- **Шторки** — перетаскивание вниз конфликтует с прокруткой содержимого.

## 4. Возможности текущего стека

`Animated` + `PanResponder` (встроены в React Native, работают на iOS, Android и в браузере):
- строка следует за пальцем, движение через `transform` на нативном драйвере;
- при отпускании пружина назад или действие.

Ограничение: отслеживание пальца идёт в JS-потоке, при сильной нагрузке возможны подлагивания. Это будет видно только на телефоне. Если подтвердится, отдельно предложу `react-native-gesture-handler` + `reanimated`: они входят в Expo SDK 58 и совместимы с архитектурой, но требуют пересборки нативного приложения. Без вашего согласия не ставлю.

Вибро-отклика нет: нет `expo-haptics`, это новая зависимость, только по согласию.

## 5. План этапа 4

**Принципы:**
- Жесты — только ускорение. У каждого действия остаётся видимая кнопка: чекбокс, открытие карточки, «⋯».
- Работают только в Soft Future и не в Хотелках, как и анимации этапа 3.
- Никаких необратимых действий свайпом.

**Компоненты:**
1. `design/SwipeableRow.tsx`:
   - строка следует за пальцем;
   - старт при |dx| > 12 px и |dx| > 1.6·|dy|;
   - касания, начатые в 28 px от левого или правого края, игнорируются;
   - действие при сдвиге ≥ 32 % ширины или быстром броске, иначе мягкий возврат;
   - открытой может быть только одна строка;
   - `touch-action: pan-y` в браузере;
   - `accessibilityActions` для экранного диктора;
   - при «уменьшить движение» без пружин.
2. Свайп **вправо** — «Выполнено»: тот же `mark(...,'complete')` с существующей отменой «Отменить». Подключаю к `CheckableListItem`, то есть Дом, Отношения, чек-листы разделов.
3. Свайп **влево** — панель действий: «Редактировать» и «В архив» (восстановимо). «Удалить» открывает существующее подтверждение. Действия «Отложить» в данных нет, его не показываю.
4. **Регулярные покупки:** свайп вправо = «Куплено» (1 шт., с существующей отменой). Предлагаю включить отдельным шагом после вашей проверки.
5. **Лекарства — без свайпов** (безопасность медицинских данных), остаются кнопки.
6. **Мои дела** (`ItemRow`): вправо = `repo.complete`, влево = меню «⋯».
7. **Перестроение списка:** скрываемая строка плавно сворачивается (высота + прозрачность, `motion.listReflow`), остальные сдвигаются без скачка.
8. **Шторки** (`SoftSheet`): закрытие перетаскиванием вниз только за верхнюю ручку (> 110 px или бросок). Прокрутка внутри не конфликтует.
9. **Долгое нажатие на строку** открывает те же действия, что свайп влево (дублирует, не заменяет).
10. **Не трогаю:** SwipeBack, листание недели и месяца, перетаскивание плиток, Входящие, Хотелки.

**Проверки:**
- автотесты логики порогов;
- эмуляция касаний в браузере (CDP touch): свайп, прерванный свайп, косой жест, прокрутка, касание у края, быстрые повторы, отмена;
- попиксельно другие темы и Хотелки;
- на телефоне — по варианту из раздела 1, вашими руками.
