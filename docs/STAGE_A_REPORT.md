## TMDB — вывод

**Уже есть в проекте:**
- **Сервер:** в `apps/server` готовый адаптер TMDB.
  - `/catalog/search` — поиск фильмов и сериалов на русском, украинском и английском, до 10 результатов с постером и годом;
  - `/catalog/{movie|tv}/{id}` — описание, жанры, длительность, ссылка на трейлер YouTube, постер w500;
  - токен хранится только на сервере (`TMDB_READ_ACCESS_TOKEN`).
- **Приложение:**
  - выбор совпадения при добавлении через «Распознать / найти» уже реализован;
  - сохраняются `catalogId` (`movie:ID`) и `posterUrl`;
  - атрибуция TMDB уже есть в коде: компонент `Credits` с логотипом;
  - в старом слое есть отдельный экран поиска `/movie-catalog`, ему нужен вход на сервер.
- **Почему сейчас не работает:**
  - токена нет;
  - сервер запущен локально (`catalog=false`);
  - сборка GitHub Pages — только клиент, сервера у неё нет.

**Условия TMDB** (официальный FAQ):
- API бесплатен для некоммерческого использования с указанием TMDB как источника;
- нужен логотип TMDB (менее заметный, чем логотип приложения) и текст «This product uses the TMDB API but is not endorsed or certified by TMDB» в разделе «О приложении / Благодарности»;
- полный текст условий (Terms of Use) прочитать автоматически не удалось — сайт запрещает это роботам. Перед подключением его нужно открыть и принять вам самой.

**Ключ:** по документации TMDB API key и Read Access Token дают одинаковый доступ. **Ни один из них нельзя класть в приложение:**
- `EXPO_PUBLIC_*` встраивается в публичный JavaScript на GitHub Pages;
- любой сможет использовать ключ от вашего имени.

**Предлагаемая архитектура:**

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| 1. Существующий сервер на Mac | `TMDB_READ_ACCESS_TOKEN` в окружении `apps/server` | Без новой инфраструктуры, код готов | Работает только пока Mac включён и сервер запущен; с телефона и с GitHub Pages недоступен |
| **2. Маленький посредник (рекомендую)** | Бесплатный Cloudflare Worker (или аналог) с теми же двумя маршрутами и форматом ответа, что у `apps/server`. Токен — секрет Worker. CORS только для вашего домена Pages и приложения, ограничение частоты. | Работает с телефона и с Pages, ключ не раскрывается | Нужна ваша учётная запись Cloudflare (бесплатно) и согласие; новая зависимость в приложении не нужна — только публичный адрес посредника |

**Что нужно от вас:**
1. Регистрация на TMDB, ключ API (тип «Personal / non-commercial»), принятие условий.
2. Выбор варианта 1 или 2. Для варианта 2 — учётная запись Cloudflare (ключ вы вставите сами в настройках Worker, мне его присылать не нужно).

**Сценарии после подключения (подэтап A2):**
- **Добавление фильма:**
  - поле названия с подсказками: постер w92, название, оригинальное название, год, «фильм» или «сериал»;
  - выбор одним нажатием;
  - **автоматического выбора нет, даже при одном совпадении**.
- **Существующие фильмы:**
  - на странице фильма без вашей обложки — кнопка «Найти постер»;
  - поиск по названию и году, список, подтверждение;
  - меняются только `posterUrl` и `catalogId`. Название, год, оценка, заметка, статус и ваши вложения не трогаются.
  - Массовой автоматической замены нет.
- **Состояния:** загрузка (скелет плитки), «Ничего не найдено», ошибка сети с кнопкой «Повторить», без сети — ручное добавление как сейчас.
- **Атрибуция TMDB** в «Профиль → О приложении» и маленькая подпись в результатах поиска.

## Питание — два варианта недели

Файлы: `food-variant-{A|B}-{320|375|390}.png`, сводка — `food-variants-A-B.png`.

| | Вариант A — вся неделя на экране | Вариант B — прокручиваемая неделя |
|---|---|---|
| Колонка блюда | 46 px (390), 44 (375), 36 (320) | 96 px на любом телефоне |
| Название | Короткое (уже есть в приложении: «Овсянка», «Курица»…), каждое слово — своя строка, длинное слово — с «…», не рвётся | Полное название до 2 строк, переносы по словам |
| Обрезано названий в демо-неделе | 7 из 17 на 390 px, 10 из 17 на 375, 13 из 17 на 320 | 0 |
| Обзор недели | Все 7 дней сразу | 3,5 дня видно, остальное — прокрутка сетки вбок; выбранный день виден сразу, есть точки-индикатор |
| Фото | Квадрат 1:1 | 4:3, одинаковые |
| Вертикальная прокрутка экрана | Как сейчас | Сохраняется: вбок двигается только сетка |
| Список выбранного дня | Под сеткой, полные названия | Под сеткой, полные названия |

**Мой вывод:**
- **Скорость планирования** выше у **A**: сразу видно, где пусто во всей неделе.
- **Читаемость** у **B** заметно лучше. В A на обычном телефоне названия режутся почти у половины блюд, на 320 px — у большинства.

Раз вам важно **видеть названия прямо в сетке**, рекомендую **B**. Список дня под сеткой есть в обоих вариантах.

Можно и гибрид: A для планирования + полный список дня под сеткой. Но названия в самой сетке останутся короткими.
